ISO-Partitionen

Installation

Ubuntu-Installer als ISO oder USB-Stick mit Autoinstall. Das Partitionslayout lässt sich nach der Installation kaum noch ändern, deshalb wird es gleich richtig angelegt.

autoinstallLUKSLVMxorriso
  • LUKS-Verschlüsselung mit LVM, /boot und /boot/efi getrennt
  • Eigene Volumes für /var, /var/tmp, /var/log, /var/log/audit, /tmp und /home
  • Mount-Optionen nodev, nosuid und noexec direkt bei der Installation
  • Größen dynamisch nach Platte, mit Reserve in der Volume Group
  • Abbruch vor dem Schreiben, nie ein stilles Standardlayout
  • Bau aus dem Original-ISO, Secure Boot bleibt erhalten
  • Desktop und Server (amd64) sowie DGX OS (arm64)

SystemSetup

Einrichtung

Richtet ein frisch installiertes System in einem Lauf ein. Die Installationsdaten können vom USB-Stick kommen, dann läuft alles offline.

bashaptClamAVoffline
  • Hostname, Netzwerk und Paketquellen
  • Benutzer und Pakete
  • VS Code, Chromium und LM Studio
  • ClamAV mit Konfiguration und geplanten Scans
  • Prüfung und Zusammenfassung am Ende

Mirror

Interne Paketquellen

Ein Mirror-Server im eigenen Netz. Clients beziehen Updates und Virensignaturen von dort statt aus dem Internet.

apt-mirror2cvdupdateApachesystemd
  • Ubuntu 24.04 und 26.04, tägliche Synchronisation
  • ClamAV-Signaturen, Update alle sechs Stunden
  • Optional NVIDIA/Mellanox (CUDA, HPC SDK, DOCA), Kubernetes, VS Code, Chromium und LM Studio
  • Ein Skript stellt Clients um und kann jeden Lauf zurücknehmen
  • Ein Skript passt kopierte Systeme an: Name, Netzwerk, Kennungen, Benutzer
  • Zugriff auf bestimmte Netze beschränkbar, passt zu gehärteten Servern

Hardening

Härtung und Prüfung

Modulares Framework mit 31 Modulen und vier Profilen. Jede Änderung wird vorher gesichert und lässt sich zurücknehmen.

CISOpenSCAPLynisPAM
  • Profile desktop, server, secure und kiosk
  • SSH, PAM, sudo, sysctl, Dateirechte und Mount-Optionen
  • auditd, AIDE, fail2ban, AppArmor und Firewall
  • --dry-run und --diff zeigen vorher, was sich ändert
  • Rollback mit Manifest und SHA256-Prüfsummen
  • Berichte aus OpenSCAP und Lynis, Ausnahmen begründet dokumentiert

Arbeitsweise

Regeln, die für alle Skripte gelten.

Idempotent

Ein zweiter Lauf ändert nichts, was schon stimmt.

Erst fragen

Zusammenfassung vor jeder Änderung, Probelauf wo möglich.

Rücknehmbar

Originaldateien werden vorher gesichert und lassen sich zurückspielen.

Offline-fähig

Installation und Updates über den eigenen Mirror oder vom USB-Stick.

Nachweisbar

Prüfberichte und dokumentierte Ausnahmen für das Audit.

Für gehärtete Systeme

Die Skripte berücksichtigen umask, Firewall und SSH-Regeln gehärteter Systeme.

Beispiel

Ein Server von der Installation bis zur Prüfung. Namen und Adressen sind Platzhalter.

# 1. Vom Stick installieren: Autoinstall legt das CIS-Layout an

# 2. Einrichten
sudo ./setup.sh

# 3. Paketquellen auf den internen Mirror umstellen
sudo MIRROR=mirror.example.com ./client_conf.sh

# 4. Erst anzeigen, dann härten
sudo ./hardening.sh --profile server --dry-run --diff
sudo ./hardening.sh --profile server

# 5. Prüfen
sudo ./hardening.sh --profile server --only 28,30 --scan
